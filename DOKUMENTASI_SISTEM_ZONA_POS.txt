1. RINGKASAN SISTEM (SYSTEM OVERVIEW)
--------------------------------------------------------------------------------
Zona POS adalah aplikasi Point of Sale (Kasir) Multi-Tenant modern berbasis web
yang dirancang untuk kebutuhan bisnis UMKM, kafe, retail, dan toko multi-cabang.
Sistem ini memfasilitasi isolasi data antar tenant (bisnis), mendukung banyak
cabang (outlet) dalam satu kepemilikan bisnis, serta memisahkan penyimpanan
inventaris antara Gudang Pusat (Storage) dan Toko/Kasir (Outlet).

Fitur unggulan:
- Multi-Tenancy dengan isolasi tenant_id pada seluruh entitas bisnis.
- Multi-Outlet & Multi-Storage: Dukungan banyak cabang dan gudang logistik.
- Manajemen Shift Kasir Terintegrasi: Kontrol modal awal, pelacakan kas, serta
  rekonsiliasi otomatis selisih kas (expected cash vs actual cash).
- POS Cepat & Responsif: Pencarian nama/SKU/barcode scanner, hold & recall order,
  serta dukungan multi-metode pembayaran (Cash, QRIS, Debit, Transfer Bank).
- Restorasi Stok Otomatis saat Refund transaksi.
- Laporan Keuangan Realtime: Omset kotor, omset bersih, HPP (Harga Pokok Penjualan),
  serta Laba Kotor (Gross Profit) terhitung otomatis.
- Audit Trail Stok & Harga: Setiap pergerakan stok dan perubahan harga tercatat
  lengkap dengan identitas pengguna dan cap waktu.

4. ARSITEKTUR DATABASE & SKEMA RELASIONAL (DATABASE & ERD SCHEMA)
--------------------------------------------------------------------------------
Database didesain secara relasional kuat dengan 19 tabel, dilengkapi constraint
foreign keys ON DELETE CASCADE / SET NULL dan indeks performa tinggi:

1.  roles:
    - id (PK), name (UNIQUE: ROLE_TENANT_OWNER, ROLE_OUTLET_MANAGER, ROLE_CASHIER).
2.  tenants:
    - id (PK), name, address, owner_name, owner_phone, owner_email, status, created_at.
3.  outlets:
    - id (PK), tenant_id (FK), name, address, manager_name, manager_phone, manager_email.
4.  users:
    - id (PK), tenant_id (FK), outlet_id (FK, nullable), name, email (UNIQUE), password,
      phone, is_active, role_id (FK).
5.  category:
    - id (PK), tenant_id (FK), code, name, parent_id (FK nullable untuk hierarki sub-kategori),
      is_parent, desc. (UNIQUE: tenant_id + code).
6.  units:
    - id (PK), tenant_id (FK), code, name, size (default 1). (UNIQUE: tenant_id + code).
7.  storages:
    - id (PK), tenant_id (FK), code, name (Gudang logistik pusat). (UNIQUE: tenant_id + code).
8.  products:
    - id (PK), tenant_id (FK), sku, barcode, name, desc, category_id (FK), unit_id (FK), is_active.
      (UNIQUE: tenant_id + sku).
9.  product_variants:
    - id (PK), product_id (FK), sku (UNIQUE), name.
10. stocks:
    - id (PK), product_id (FK), variant_id (FK), outlet_id (FK nullable), storage_id (FK nullable),
      quantity, minimum.
11. stock_history:
    - id (PK), stock_id (FK), stock_in_out, quantity, status (IN/OUT),
      type (SALE, PURCHASE, ADJUSTMENT, TRANSFER), remarks, user_id (FK), created_at.
12. prices:
    - id (PK), product_id (FK), outlet_id (FK), selling_price, purchase_price,
      discount_percentage, discount_amount, tax_percentage, tax_amount.
      (UNIQUE: product_id + outlet_id).
13. price_history:
    - id (PK), price_id (FK), selling_price, purchase_price, discount_percentage,
      discount_amount, tax_percentage, tax_amount, user_id (FK), created_at.
14. customers:
    - id (PK), tenant_id (FK), name, phone, email, created_at. (UNIQUE: tenant_id + phone).
15. cashier_shifts:
    - id (PK), outlet_id (FK), user_id (FK), start_cash, expected_cash, actual_cash,
      total_cash_in, total_cash_out, status (OPEN, CLOSED), opened_at, closed_at.
16. transactions:
    - id (PK), trx_no (UNIQUE), tenant_id (FK), outlet_id (FK), user_id (FK), customer_id (FK),
      shift_id (FK), subtotal, discount, order_discount, order_discount_type, order_discount_rate,
      voucher_code, voucher_discount, tax, grand_total, status (DRAFT, COMPLETED, REFUNDED),
      due_date, created_at, updated_at.
17. transaction_items:
    - id (PK), trx_id (FK), outlet_id (FK), product_id (FK), variant_id (FK),
      quantity, base_price (HPP), unit_price, discount, tax, subtotal.
18. payments:
    - id (PK), trx_id (FK), payment_method (CASH, QRIS, TRANSFER, DEBIT, TEMPO), amount,
      status (PAID, UNPAID, PARTIAL, REFUNDED), reference, due_date, notes, paid_at.
19. transaction_history:
    - id (PK), trx_id (FK), trx_no, outlet_id (FK), customer_id (FK), subtotal,
      discount, order_discount, voucher_code, voucher_discount, tax, grand_total, status,
      user_id (FK), created_at.
20. cash_movements:
    - id (PK), shift_id (FK), tenant_id (FK), outlet_id (FK), user_id (FK),
      type (CASH_IN, CASH_OUT), amount, category (Operasional, Bahan, Tambah Modal, Kurir, Lainnya),
      notes, created_at.
21. promotions:
    - id (PK), tenant_id (FK), outlet_id (FK, nullable), code (UNIQUE per tenant),
      name, description, discount_type (PERCENT, FIXED), discount_value, min_order_amount,
      max_discount_amount, start_date, end_date, usage_limit, times_used, is_active,

22. receipt_settings:
    - id (PK), tenant_id (FK), outlet_id (FK, nullable), paper_size (VARCHAR(10) DEFAULT '58mm'),

      instagram (VARCHAR(100)), website (VARCHAR(150)), footer_note (TEXT),
      show_logo (BOOLEAN DEFAULT TRUE), show_social_media (BOOLEAN DEFAULT TRUE),

23. suppliers:
    - id (PK), tenant_id (FK), name (VARCHAR(150)), contact_person (VARCHAR(100)),
      phone (VARCHAR(50)), email (VARCHAR(100)), address (TEXT),

--------------------------------------------------------------------------------
5. KEAMANAN & AUTENTIKASI (SECURITY, JWT & RBAC)
--------------------------------------------------------------------------------
- Algoritma Password : BCrypt (Cost Factor 10).
- Token Standar      : JWT (HMAC-SHA256) via header `Authorization: Bearer <token>`.
- Token Expiration   :
  * Owner & Manager  : 1 jam (3.600.000 ms) untuk keamanan data manajerial.
  * Kasir (Cashier)  : 24 jam (86.400.000 ms) agar kasir tidak ter-logout saat
                       jam operasional shift kerja sedang berlangsung.
- Role Hierarchy     :
  1. `ROLE_TENANT_OWNER`   : Hak akses penuh ke seluruh tenant, semua cabang, laporan keuangan,
                             manajemen outlet, dan pembuatan user staf.
  2. `ROLE_OUTLET_MANAGER` : Hak akses ke cabang yang ditugaskan, manajemen stok, harga,
                             dan laporan performa outlet.
  3. `ROLE_CASHIER`        : Akses operasional harian: Buka/Tutup Shift, Transaksi POS,
                             Hold/Recall Order, dan Pendaftaran Pelanggan baru.
- CORS Configuration : Terbuka untuk seluruh origin pengembang dengan dukungan credentials
                       dan methods: GET, POST, PUT, PATCH, DELETE, OPTIONS.


--------------------------------------------------------------------------------
6. MODUL & ALUR BISNIS UTAMA (BUSINESS LOGIC & WORKFLOWS)
--------------------------------------------------------------------------------

6.1. MULTI-TENANCY & CABANG (OUTLET)
- Setiap request diisolasi berdasarkan `tenantId` dari token JWT pengguna yang login.
- Tenant Owner dapat menambahkan cabang baru melalui menu Outlets & Users.
- Pengguna yang memiliki akses multi-cabang dapat beralih cabang via dropdown di Navbar.

6.2. MASTER DATA (KATALOG & SATUAN)
- Mendukung Kategori bertingkat (parent-child category) untuk pengelompokan produk.
- Satuan unit barang (CUP, PCS, PACK, BOX) dengan faktor ukuran (size).
- Gudang Pusat (Storage) dapat didaftarkan terpisah dari outlet untuk sentralisasi logistik.

6.3. KATALOG PRODUK & PENETAPAN HARGA
- Produk memiliki SKU unik per tenant serta Barcode untuk pemindaian scanner fisik.
- Dukungan varian produk (contoh: Ukuran Small, Medium, Large atau Varian Rasa).
- Penetapan Harga Bersifat Multi-Tier: Harga jual (`sellingPrice`) dan harga modal (`purchasePrice`)
  dapat disetel berbeda di setiap cabang outlet.
- Diskon dan Pajak per produk dapat dikonfigurasi dalam persentase atau nominal langsung.
- Setiap kali harga diubah, riwayat harga lama otomatis disimpan di tabel `price_history`.

6.4. MANAJEMEN STOK & MUTASI ATOMIK
- Tabel `stocks` menyimpan inventaris secara spesifik: apakah stok berada di Toko/Outlet
  atau di Gudang Pusat (Storage).
- Tiga Jenis Mutasi Inventaris:
  1. Transfer Stok (Gudang -> Outlet): Stok gudang dikurangi dan stok outlet ditambahkan
     dalam satu transaksi atomik database (`@Transactional`).
  2. Penyesuaian Stok (Stock Opname): Sinkronisasi hitungan fisik dengan sistem, dilengkapi
     alasan (remarks) dan batas minimum stok untuk alert.
  3. Pembelian / Barang Masuk (Purchase): Penambahan stok baru dari supplier ke gudang atau outlet.
- Peringatan Stok Menipis: Otomatis mendeteksi produk yang stoknya `<= minimum`.
- Setiap mutasi mencatat data rinci ke `stock_history` (IN/OUT, delta, tipe, dan user penanggung jawab).

6.5. MANAJEMEN SHIFT KASIR & REKONSILIASI KAS LACI (PETTY CASH CASH IN - CASH OUT)
- Kasir WAJIB membuka shift sebelum dapat melayani transaksi pembayaran.
- Buka Shift: Memasukkan nominal Kas Awal (Modal Pecahan/Float). Status shift menjadi `OPEN`.
- Operasional Kas Masuk & Kas Keluar (Petty Cash):
  * Pengeluaran Darurat Laci (Cash Out): Misal beli es batu kristal, galon air, plastik kresek,
    lakban, bayar kurir paket COD. Kasir mencatat tipe CASH_OUT, nominal, kategori biaya, dan keterangan.
  * Tambahan Modal / Suntik Kas (Cash In): Misal owner menyuntikkan uang receh pecahan kembalian.
    Kasir mencatat tipe CASH_IN, nominal, kategori, dan keterangan.
  * Proteksi Anti-Overdraft Kasir: Sistem secara otomatis memvalidasi bahwa pengeluaran kas keluar
    TIDAK BOLEH melebihi saldo fisik uang tunai yang ada di laci saat itu.
- Selama Shift:
  * Formula Realtime Saldo Laci:
    `expectedCash = startCash + totalCashSales + totalCashIn - totalCashOut`
- Tutup Shift & Rekonsiliasi Kas Bersih:
  * Kasir menghitung fisik uang tunai di laci dan memasukkan `actualCash`.
  * Sistem membandingkan kas fisik aktual dengan estimasi sistem secara presisi.
  * Berkat pencatatan kas masuk & kas keluar yang disiplin, kas fisik laci seimbang (Rp 0 selisih).
  * Data `total_cash_in` dan `total_cash_out` dibekukan (snapshot) permanen ke tabel `cashier_shifts`.
- Cetak Struk Rekap Shift (Z-Report & X-Report Thermal POS):
  * Z-Report (Tutup Shift): Struk resmi penutupan shift kasir berformat thermal 58mm/80mm yang memuat
    waktu buka/tutup, kasir, modal awal, penjualan tunai & non-tunai, kas masuk, kas keluar,
    estimasi laci, kas fisik aktual, selisih kas, rincian mutasi kas kecil, dan kolom tanda tangan kasir & manajer.
    Struk ini wajib dimasukkan ke dalam amplop setoran kasir bersama uang tunai fisik untuk disetorkan ke bank.
  * X-Report (Interim): Pembacaan sementara kas berjalan kasir tanpa menutup sesi shift aktif.

6.6. TRANSAKSI POS (POINT OF SALE)
- Pencarian produk instan melalui nama, SKU, atau pemindai Barcode (auto-enter).
- Fitur Parkir Transaksi (Hold Order):
  * Jika ada pelanggan yang ingin menambah barang atau antrean tertunda, kasir dapat
    mengklik "Parkir Transaksi" (Hold). Keranjang disimpan ke database dengan status `DRAFT`.
  * Kasir bebas melayani pelanggan berikutnya tanpa kehilangan keranjang sebelumnya.
- Pemanggilan Kembali (Recall Order):
  * Kasir membuka daftar pesanan yang di-hold dan memuatnya kembali ke keranjang belanja.
- Pembayaran Cepat:
  * Dukungan CASH, QRIS, DEBIT, dan TRANSFER.
  * Tombol denominasi cepat uang pas, +Rp 10.000, +Rp 20.000, +Rp 50.000, +Rp 100.000.
  * Hitungan kembalian otomatis.
- Pengurangan Stok Otomatis: Begitu checkout sukses, kuantitas stok di outlet berkurang
  dan dicatat ke riwayat dengan referensi No. Transaksi.
- Struk Belanja: Format struk kasir thermal 58mm/80mm siap cetak dengan perintah cetak browser.

6.7. PENGEMBALIAN DANA (REFUND) & RESTORASI INVENTARIS
- Transaksi `COMPLETED` dapat di-refund oleh manajer/owner dengan menyertakan alasan.
- Logika Atomik Refund:
  * Status transaksi diubah menjadi `REFUNDED`.
  * Status pembayaran diubah menjadi `REFUNDED`.
  * Seluruh item barang yang dibeli otomatis dikembalikan (restorasi) ke stok outlet terkait.
  * Pergerakan stok masuk (IN) tercatat pada `stock_history` dengan tipe `ADJUSTMENT` / alasan refund.

6.8. CRM / MANAJEMEN PELANGGAN
- Pencatatan data pelanggan (Nama, Nomor WhatsApp/Telepon, Email).
- Pendaftaran instan pelanggan baru langsung dari layar POS kasir saat melayani transaksi.
- Pelacakan riwayat transaksi belanja pelanggan untuk analisis loyalitas.

6.9. DASHBOARD LAPORAN & LABA KOTOR (GROSS PROFIT)
- Omset Kotor (Gross Sales) vs Omset Bersih (Net Sales).
- Laba Kotor (Gross Profit) = `Total Penjualan Bersih - Total HPP (Harga Pokok Penjualan)`.
- Margin Persentase Profit terhitung otomatis.
- Ringkasan penerimaan per metode pembayaran (Berapa kas fisik, QRIS, EDC Debit, dan Transfer).
- Tren harian volume dan nilai transaksi.

6.10. KLASTER 3: DISKON GLOBAL NOTA & KODE VOUCHER PROMOSI
- Mengatasi keterbatasan diskon yang sebelumnya hanya bisa disetel per-item barang di master data.
- Dua Lapisan Diskon Global Nota:
  1. Diskon Nota Manual (Order Discount):
     * Fleksibilitas format: Kasir dapat memilih mode Rupiah langsung (FIXED, misal Rp 15.000)
       atau Persentase (PERCENT, misal Diskon Member 10%).
     * Tersedia tombol preset nominal cepat (5k, 10k, 20k, 50k) dan persen (5%, 10%, 15%, 20%).
     * Nominal diskon memotong total tagihan belanja secara langsung dan realtime.
  2. Kode Voucher Promosi (Promotion Voucher Coupon):
     * Input kode voucher promo unik (contoh: HEMAT10, GRANDOPENING, MEMBER5, DISKON25K).
     * Validasi Syarat Promo Komprehensif:
       - Status keaktifan voucher (`is_active`).
       - Periode berlaku (`start_date` s/d `end_date`).
       - Batas kuota pemakaian total (`usage_limit` vs `times_used`).
       - Batas minimum pembelanjaan nota (`min_order_amount`).
       - Plafon maksimal potongan (`max_discount_amount`) untuk voucher bertipe persentase.
       - Validitas cabang outlet (apakah voucher berlaku general atau khusus cabang tertentu).
     * Chip Rekomendasi Voucher Aktif: Kasir disajikan pill tombol voucher aktif yang dapat
       langsung diklik untuk memasang voucher tanpa perlu mengetik manual.
  3. Integritas Transaksional & Concurrency Locking:
     * Saat checkout diproses, penggunaan kupon voucher dikunci menggunakan Pessimistic Write Lock
       (`SELECT ... FOR UPDATE`) pada tabel `promotions`, mencegah kuota voucher terlewati
       akibat checkout paralel dari banyak kasir pada milidetik yang sama.
     * Nilai diskon nota (`order_discount`) dan voucher (`voucher_discount`) disimpan permanen
       ke tabel `transactions` dan `transaction_history` untuk audit trail finansial 100% presisi.
  4. Persistensi DRAFT (Hold & Recall Order):
     * Jika transaksi di-hold (parkir), data Diskon Nota dan Kode Voucher yang sudah dipasang
       tetap tersimpan rapi pada DRAFT dan otomatis terisi kembali saat pesanan di-recall.
  5. Transparansi Cetak Struk Belanja Kasir:
     * Struk thermal kasir memuat rincian terpisah: Subtotal Produk, Diskon Produk, Diskon Nota,
       Voucher Promo, Pajak PPN, dan Grand Total Pembayaran. Pelanggan menerima rincian bukti
       hemat yang transparan.

6.11. KLASTER 4: HARDWARE & KUSTOMISASI STRUK BELANJA (58MM & 80MM)
- Mengatasi masalah header dan footer struk thermal yang sebelumnya statis/hardcoded ("ZONA POS UMKM").
- Kustomisasi Identitas Toko Per-Cabang / Per-Tenant:
 * Logo Toko: Mendukung unggah berkas gambar lokal (otomatis dikonversi ke Base64 Data URL)
   maupun URL gambar online eksternal, dilengkapi filter cetak monokrom untuk ketajaman thermal optimal.
 * Nama Bisnis / Outlet Toko: Header nota besar & tebal sesuai identitas merek dagang.
 * Alamat Lengkap: Lokasi toko yang jelas untuk keabsahan struk belanja.
 * Kontak Resmi: Nomor Telepon / WhatsApp dan akun Instagram resmi toko.
 * Catatan Kaki Struk (Footer Note): Pesan penutup, kebijakan retur garansi barang, ucapan
   terima kasih, atau info promo yang dapat disesuaikan sesuka hati.
 * Sakelar Visibilitas: Toggle on/off untuk logo dan media sosial.
- Fleksibilitas Format Hardware Printer Thermal (58mm vs 80mm):
 * Format 58mm (Mini Printer Bluetooth / USB Portable): Lebar cetak ~48mm (32 karakter teks).
   Didesain khusus untuk kasir mobile, kedai kopi, food truck, dan meja pembayaran sempit.
 * Format 80mm (Desktop Thermal Ritel / Supermarket): Lebar cetak ~72mm (48 karakter teks).
   Didesain untuk ritel besar, supermarket, resto dengan banyak rincian item belanja.
- Aturan Cetak Presisi CSS Thermal (@media print):
 * Menerapkan reset margin browser (@page { margin: 0; size: auto; }) dan isolasi kontainer
   cetak (#printable-receipt { width: 48mm / 72mm !important; padding: 3mm !important; }),
   menghilangkan pemotongan teks samping dan header/footer URL bawaan browser web.
- Pratinjau Interaktif Real-Time (Live Thermal Receipt Preview):
 * Panel pratinjau di sebelah kanan form pengaturan merespons setiap ketikan secara instan,
   menampilkan simulasi kertas thermal fisik dengan tepi robek (tear border) dan font monospaced.
 * Dilengkapi tombol "Tes Cetak Sampel" untuk uji coba langsung ke printer thermal fisik kasir.
- Mekanisme Fallback Cerdas (Multi-Tenant & Multi-Outlet Inheritance):
 * Pengaturan dipetakan berdasarkan `(tenant_id, outlet_id)`.
 * Jika cabang outlet belum memiliki pengaturan khusus, sistem otomatis menggunakan default tenant
   atau membuat konfigurasi awal cerdas dari data nama dan alamat outlet yang sudah terdaftar.

6.12. KLASTER 5: LAPORAN & EKSPOR DATA AKUNTANSI (EXCEL & PDF)
- Mengatasi kendala pemilik toko (owner) dan akuntan dalam menghitung pajak bulanan atau integrasi
  ke software akuntansi pihak ketiga (seperti Accurate Online, Jurnal by Mekari, Zahir Accounting).
- Format Ekspor Universal:
  1. Excel Native (.xlsx via SheetJS):
     * Multi-Sheet Workbook: File Excel yang diunduh pada menu Laporan Omset memuat 3 sheet terpisah:
       - Sheet 1: "Ringkasan Omset & Laba" (KPI Finansial, Cash vs QRIS vs EDC Debit vs Transfer).
       - Sheet 2: "Rincian Margin Produk (COGS)" (Nama Produk, Qty Terjual, Revenue, HPP, Gross Profit, Margin %).
       - Sheet 3: "Audit Transaksi Kasir" (Seluruh daftar transaksi pada periode terpilih).
     * Format Sel & Tipe Data Presisi: Kolom numerik, mata uang, dan tanggal di-encode dengan tipe data
       angka asli (bukan teks), sehingga rumus Excel seperti `SUM()`, `AVERAGE()`, atau PivotTable
       dapat langsung diaplikasikan tanpa perlu konversi manual.
     * Lebar Kolom Otomatis (Auto-fit Column Widths): Kolom disesuaikan dengan panjang teks terpanjang,
       mencegah tampilan error pemotongan teks atau sel `###` pada Microsoft Excel.
  2. CSV Akuntansi Berstandar Internasional (.csv with UTF-8 BOM):
     * Menambahkan byte sequence UTF-8 BOM (`\uFEFF`) di awal berkas CSV untuk memastikan aplikasi Excel
       di sistem operasi Windows membuka huruf dan angka Indonesia secara mulus tanpa korupsi encoding.
  3. Dokumen Resmi Eksekutif & PDF Vektor (Letter / A4 Print Engine):
     * Pratinjau Dokumen Eksekutif ("ReportPrintModal"): Layout kertas formal dilengkapi Kop Surat resmi
       toko, informasi kontak, metadata pencetakan, tabel data bergaris rapi dengan zebra striping,
       kotak total di baris penutup, dan kolom pengesahan tanda tangan ganda ("Disiapkan Oleh" & "Disetujui Oleh").
     * CSS Print Layout Presisi (@page { size: A4 portrait; margin: 8mm 10mm; }): Menghasilkan dokumen
       PDF vektor berkualitas tinggi yang siap dicetak ke printer kertas atau disimpan sebagai berkas PDF
       melalui dialog bawaan browser.
- Penerapan Menyeluruh di 3 Modul Finansial:
  * Halaman Laporan & Omset (`DashboardReports.jsx`): Dilengkapi filter rentang tanggal cepat (Hari Ini,
    7 Hari, 30 Hari, Bulan Ini, dan Kustom Tanggal) serta tombol ekspor Excel dan cetak PDF.
  * Halaman Riwayat Transaksi (`TransactionsPage.jsx`): Ekspor seluruh transaksi terfilter menjadi
    Buku Jurnal Penjualan Kasir (Sales Journal) lengkap dengan rincian diskon nota, voucher, dan status bayar.
  * Halaman Riwayat Shift Kasir (`ShiftsPage.jsx`): Ekspor seluruh rekam jejak shift kasir menjadi
    Laporan Rekonsiliasi Kas Laci (Cash Drawer Accountability) lengkap dengan modal awal, mutasi kas kecil,
    estimasi sistem, fisik laci, dan selisih kas.

6.13. KLASTER 6: MANAJEMEN PENGADAAN (SUPPLY CHAIN & SUPPLIER)
--------------------------------------------------------------------------------
6.13.1. Master Data Supplier & Purchase Order (PO Bahan Baku/Barang):
- Masalah Sebelumnya:
  Penerimaan barang masuk hanya meminta catatan keterangan teks biasa tanpa asosiasi
  ke data vendor, tanpa tracking termin pembayaran (COD/Tempo), dan tanpa analisis
  perubahan harga beli modal bahan baku.
- Solusi Enterprise:
  1. Master Data Mitra Pemasok (Vendor/Supplier):
     * Data komprehensif: Nama Perusahaan Vendor, Kontak Sales (PIC), Nomor Telepon / WA,
       Email, Alamat Gudang Pengiriman, dan Termin Pembayaran resmi (COD, NET 7, NET 14,
       NET 30, TEMPO).
     * Filter multi-tenant ketat: Vendor terisolasi per tenant_id dengan constraint
       unik pada nama supplier.
  2. Tracking Harga Modal Terakhir (Last Purchase Price Tracking):
     * Setiap kali kasir/gudang memilih produk pada form "Penerimaan Barang Masuk (PO)",
       sistem langsung mengeksekusi query efisien untuk mendeteksi harga beli modal terakhir
       dari transaksi pengadaan sebelumnya.
     * Analisa Fluktuasi Harga Otomatis: Sistem secara realtime membandingkan harga modal baru
       terhadap harga sebelumnya, menampilkan badge indikator visual:
       - Merah (▲ Naik +Rp X / +Y%): Peringatan kenaikan harga bahan baku.
       - Hijau (▼ Turun -Rp X / -Y%): Indikator efisiensi / potongan harga vendor.
       - Netral: Harga stabil sama persis.
  3. Pencatatan Purchase Order & Update Master Harga Modal:
     * Menghasilkan Nomor Dokumen PO unik otomatis (`PO-YYYYMMDD-XXXX`).
     * Menghitung total estimasi nilai pengadaan secara presisi (`quantity * purchase_price`).
     * Mendukung nomor faktur/invoice eksternal dari vendor (`invoice_no`).
     * Mengupdate master harga beli (`prices.purchase_price`) secara transparan dan mencatat
       audit mutasi kartu stok (`StockHistory` bertipe `PURCHASE`).

6.13.2. Generator Cetak Barcode Code 128 & Price Tag Rak Toko:
- Masalah Sebelumnya:
  Toko ritel dan minimarket baru kesulitan membuat label barcode untuk produk yang belum
  memiliki barcode pabrik. Tidak ada fasilitas cetak price tag rak yang siap ditempel
  di rak etalase minimarket.
- Solusi Enterprise:
  1. Engine Generator Barcode Vektor Code 128 (Pure Mathematical SVG):
     * Mengimplementasikan standar internasional Code 128 Subset B dengan perhitungan
       checksum Modulo 103 secara presisi.
     * Barcode digambar dalam bentuk vektor `<svg>` (bukan gambar bitmap raster), menghasilkan
       garis barcode yang luar biasa tajam (razor-sharp) pada printer label thermal 203 DPI
       maupun printer laser/inkjet A4, sehingga langsung terbaca 100% oleh pemindai barcode
       fisik (1D Laser / CCD Scanner) dalam waktu <1 milidetik.
  2. Tiga Format Cetak Label Fleksibel:
     * Format 1: Price Tag Rak Minimarket (Ukuran 60mm x 40mm)
       Memuat Header Nama Toko, Tanggal Cetak, Nama Produk Bold, Kategori & Satuan Unit,
       Kotak Harga Jual Ritel Besar & Mencolok (e.g. "Rp 18.500"), serta Barcode Code 128
       dan SKU di bagian bawah.
     * Format 2: Stiker Barcode Produk Mini (Ukuran 40mm x 30mm)
       Cocok untuk ditempel langsung di kemasan botol, pakaian, snack, atau plastik barang.
     * Format 3: Lembar Kertas Stiker Grid A4 (Universal Tom & Jerry 108 / 121)
       Layout grid 3 kolom x 8 baris (24 label per lembar A4), memungkinkan toko mencetak
       seluruh label produk menggunakan printer kertas biasa tanpa harus membeli printer barcode khusus.
  3. Batch Printing & Kuantitas Mandiri:
     * Pengguna dapat memilih banyak produk sekaligus (Select All) dan mengatur jumlah lembar
       label per barang (misal: Produk A cetak 5 lembar, Produk B cetak 10 lembar).
     * Tombol "Cetak Barcode" tersedia baik di header katalog maupun per-baris tabel produk.

7. SPESIFIKASI REST API ENDPOINT (LENGKAP)
--------------------------------------------------------------------------------
Prefix Dasar: `/api/v1`

A. AUTHENTICATION (`/auth`)
- POST `/auth/login`               : Autentikasi user & pengembalian token JWT.
- POST `/auth/register-tenant`     : Pendaftaran tenant bisnis baru, outlet default, & akun owner.
- GET  `/auth/me`                  : Profil pengguna yang sedang login.

B. OUTLETS (`/outlets`)
- GET  `/outlets`                  : Daftar semua cabang outlet milik tenant.
- POST `/outlets`                  : Tambah cabang baru.
- PUT  `/outlets/{id}`             : Perbarui informasi cabang.

C. USERS (`/users`)
- GET   `/users?outletId={id}`     : Daftar user staf per cabang atau seluruh tenant.
- POST  `/users`                   : Buat akun staf baru (Owner, Manager, Kasir).
- PUT   `/users/{id}`              : Perbarui profil staf.
- POST  `/users/{id}/reset-password`: Reset kata sandi staf.
- PATCH `/users/{id}/toggle-status`: Mengaktifkan / menonaktifkan akun staf.

D. MASTER DATA (`/categories`, `/units`, `/storages`)
- GET  `/categories`               : Daftar seluruh kategori produk.
- POST `/categories`               : Tambah kategori baru.
- GET  `/units`                    : Daftar satuan barang.
- POST `/units`                    : Tambah satuan baru.
- GET  `/storages`                 : Daftar gudang logistik pusat.
- POST `/storages`                 : Tambah gudang baru.

E. PRODUK & HARGA (`/products`, `/prices`)
- GET  `/products?outletId={id}`   : Ambil katalog produk lengkap dengan harga outlet & stok.
- GET  `/products/{id}`            : Detail produk spesifik.
- POST `/products`                 : Buat produk baru.
- POST `/products/{id}/variants`   : Tambah varian produk baru.
- POST `/prices`                   : Tetapkan harga jual/beli, diskon, & pajak per outlet.
- GET  `/prices/history/{priceId}` : Riwayat perubahan harga.

F. INVENTARIS & STOK (`/stocks`)
- GET  `/stocks/outlet/{outletId}` : Daftar stok pada cabang outlet tertentu.
- GET  `/stocks/storage/{storageId}`: Daftar stok pada gudang pusat tertentu.
- GET  `/stocks/low-stock/{outletId}`: Peringatan barang yang stoknya di bawah batas minimum.
- POST `/stocks/adjustment`        : Stock opname / koreksi kuantitas stok manual.
- POST `/stocks/purchase`          : Pencatatan barang masuk dari pemasok (purchase).
- POST `/stocks/transfer`          : Mutasi pemindahan stok dari Gudang Pusat ke Outlet.
- GET  `/stocks/history/{stockId}` : Log riwayat pergerakan stok lengkap.

G. SHIFT KASIR & KAS KECIL (`/shifts`)
- POST `/shifts/open`              : Membuka shift kasir dengan kas awal.
- POST `/shifts/{id}/close`        : Menutup shift & rekonsiliasi kas fisik laci.
- GET  `/shifts/active`            : Status shift kasir yang sedang aktif untuk user yang login.
- GET  `/shifts/outlet/{outletId}` : Riwayat seluruh sesi shift di outlet tertentu.
- POST `/shifts/movements`         : Mencatat Kas Masuk / Kas Keluar kasir (Petty Cash).
- GET  `/shifts/{shiftId}/movements`: Mengambil daftar seluruh mutasi kas kecil per shift.
- GET  `/shifts/active/movements`  : Mengambil riwayat mutasi kas kecil shift aktif saat ini.

H. TRANSAKSI KASIR (`/transactions`)
- POST `/transactions/hold`        : Simpan sementara keranjang belanja (DRAFT).
- POST `/transactions/checkout`    : Eksekusi checkout (mendukung metode tunggal, Split Payment campuran, dan Kasbon/Tempo), potong stok dengan Pessimistic Locking, & cetak struk (COMPLETED).
- POST `/transactions/{id}/refund` : Batalkan transaksi, ubah status, & kembalikan stok (REFUNDED).
- GET  `/transactions?outletId={id}&status={status}`: Cari transaksi berdasarkan outlet & status.
- GET  `/transactions/{id}`        : Detail lengkap transaksi, rincian item, daftar pembayaran (payments), & status tempo.

I. PELANGGAN & MANAJEMEN PIUTANG / KASBON (`/customers`)
- GET  `/customers`                : Daftar seluruh pelanggan tenant lengkap dengan saldo kasbon aktif & jumlah nota belum lunas (Zero N+1 batch query).
- POST `/customers`                : Registrasi pelanggan baru.
- GET  `/customers/{id}`           : Detail data pelanggan & saldo piutang kasbon.
- GET  `/customers/{id}/transactions`: Riwayat transaksi belanja pelanggan terkait.
- GET  `/customers/{id}/unpaid-bills`: Daftar nota tagihan kasbon/tempo yang belum lunas per pelanggan.
- POST `/customers/{id}/settle-debt` : Mencatat pelunasan/cicilan kasbon, audit status pembayaran, & sinkronisasi otomatis laci kasir (Cash In).

J. LAPORAN & ANALITIK (`/reports`)

- GET  `/reports/gross-profit?outletId={id}&startDate={d}&endDate={d}`: Laporan HPP & Laba Kotor.

K. VOUCHER & PROMOSI (`/promotions`) [KLASTER 3]

- GET  `/promotions/all`               : Mengambil seluruh master voucher (untuk Manager/Owner).

- GET  `/receipt-settings?outletId={outletId}`: Mengambil konfigurasi struk aktif untuk cabang outlet terkait (atau fallback default).

M. EKSPOR DATA & AKUNTANSI (`/transactions/export`, `/reports/sales/export`) [KLASTER 5]

N. SUPPLIER & PURCHASE ORDER (`/suppliers`) [KLASTER 6]

- GET    `/suppliers/last-price?productId={pId}&variantId={vId}`: Mengambil harga beli modal terakhir untuk analisa fluktuasi.

8. PANDUAN INSTALASI & MENJALANKAN SISTEM (RUN & SETUP GUIDE)
--------------------------------------------------------------------------------

A. PRASYARAT
1. Java Development Kit (JDK) versi 17 atau lebih tinggi.
2. PostgreSQL Server (Database aktif dengan nama `zona_pos_db`).
3. Node.js versi 18+ dan NPM.

B. SETUP BACKEND
1. Konfigurasi kredensial database di `zona_pos_backend/src/main/resources/application.yml`:
   ```yaml
   spring:
     datasource:
       url: jdbc:postgresql://127.0.0.1:5433/zona_pos_db
       username: postgres
       password: your_password
   ```
2. Jalankan backend menggunakan skrip siap pakai:
   ```cmd
   start-backend.bat
   ```
   Atau via Maven CLI:
   ```cmd
   mvn spring-boot:run
   ```
   * Flyway akan otomatis mengeksekusi migrasi skema tabel (V1) dan demo data (V2).

C. SETUP FRONTEND
1. Masuk ke direktori frontend dan instal paket dependensi:
   ```cmd
   npm install
   ```
2. Jalankan frontend dev server menggunakan skrip:
   ```cmd
   start-frontend.bat
   ```
   Atau via NPM CLI:
   ```cmd
   npm run dev
   ```
3. Buka aplikasi di browser pada alamat:
   `http://localhost:5173`

10. KATALOG FITUR LENGKAP & PANDUAN TEKNIS PEMAKAIAN (OPERATIONAL & CASHIER MANUAL)
--------------------------------------------------------------------------------
Dokumentasi ini adalah panduan operasional hidup (Living Documentation) yang wajib
diperbarui setiap kali ada penambahan atau perubahan fitur pada sistem Zona POS.
Berikut adalah daftar seluruh fitur yang tersedia serta panduan teknis pemakaiannya:

10.1. LAYAR KASIR POS (SPEED OF SERVICE, HOTKEYS & SCANNER BARCODE)
------------------------------------------------------------------
- Lokasi Menu : Sidebar -> "Kasir POS" (Akses: Kasir, Manager, Owner).
- Persyaratan : Shift kasir harus sudah dalam kondisi "OPEN" (Buka Shift).
- Panduan Tombol Pintas Keyboard (Keyboard-Driven Hotkeys):
  * [F2] : Fokus instan ke kolom pencarian / scanner barcode.
  * [F4] : Parkir Transaksi (Hold Order) saat pelanggan menunda pembayaran.
  * [F7] : Panggil Kembali Antrean (Recall Order).
  * [F8] : Buka dialog Pembayaran / Checkout Cepat.
  * [Esc]: Batalkan modal aktif / kembali ke layar utama kasir.
  * [Enter]: Saat pemindaian barcode selesai atau hasil pencarian produk tunggal,
             otomatis menambahkan produk ke keranjang tanpa klik mouse.
- Pemilihan Varian Produk Cepat:
  * Jika produk memiliki varian (misal: Size M/L, Dingin/Panas), klik pada kartu
    produk akan memunculkan modal dialog "Pilih Varian Produk" yang menampilkan
    stok realtime masing-masing varian.
  * Kasir juga dapat langsung mengklik tombol pill "+ Varian" di bagian bawah kartu produk.
  * Setiap penambahan produk memicu audio feedback sintetis (retail beep sound).
- Pemilihan Pelanggan (Customer Selector):
  * Kasir dapat memilih pelanggan terdaftar dari dropdown atau menekan tombol "+"
    untuk mendaftarkan pelanggan baru secara cepat tanpa keluar dari kasir.
- Denominasi Uang Tunai Cepat:
  * Modal pembayaran tunai dilengkapi tombol nominal instan: Uang Pas, Rp 10.000,
    Rp 20.000, Rp 50.000, Rp 100.000, dan Rp 200.000 untuk mempercepat transaksi.
- Pembayaran Campuran (Split Payment):
  * Cara Menggunakan: Pada dialog checkout kasir (Hotkeys: F8 / tombol "Bayar Cepat"), tekan tab/opsi "SPLIT".
  * Kasir dapat memecah pembayaran satu transaksi ke berbagai metode (contoh: Total tagihan Rp 135.000 dibayar Tunai Rp 50.000 dan sisanya Rp 85.000 via QRIS).
  * Pilihan metode per baris: Tunai (CASH), QRIS, Transfer Bank, Debit EDC, dan Kasbon/Tempo.
  * Tombol "+ Tambah Baris": Kasir dapat menambah baris pembayaran sesuai keinginan. Sisa tagihan otomatis dikalkulasikan pada baris baru.
  * Live Calculation: Kotak ringkasan otomatis memvalidasi nominal alokasi: "Kurang Rp ..." (merah) jika alokasi belum cukup, atau "✓ Pas / Kembalian Tunai" (hijau) jika pembayaran terpenuhi.
  * Thermal Struk: Struk kasir mencetak rincian seluruh metode pembayaran campuran secara transparan.
- Kasbon / Pembayaran Tempo Pelanggan (Credit & Receivables):
  * Cara Menggunakan: Pada dialog checkout kasir (Hotkeys: F8), tekan opsi "KASBON".
  * Hak Istimewa Pelanggan Terdaftar: Fitur ini diproteksi ketat hanya untuk pelanggan yang terdaftar (member). Jika belum memilih pelanggan, sistem memandu kasir untuk memilih dari daftar atau menekan "+ Baru" tanpa menutup keranjang.
  * Tanggal Jatuh Tempo: Kasir memasukkan tanggal jatuh tempo pelunasan (otomatis default: +14 hari ke depan).
  * Dukungan Uang Muka (DP): Kasir dapat menginput nominal uang muka / DP (via Tunai, QRIS, Transfer, atau Debit) dan sisanya otomatis dicatat sebagai saldo Kasbon/Tempo.
  * Integritas Transaksional: Transaksi berstatus COMPLETED (stok barang dipotong secara aman via Pessimistic Lock), sedangkan baris pembayaran bertempo berstatus UNPAID (atau PARTIAL).
  * Struk Kasbon: Struk kasir thermal otomatis menampilkan status tegas "STATUS: KASBON / TEMPO (BELUM LUNAS)" beserta tanggal jatuh tempo penagihannya.
- Diskon Global Nota & Kode Voucher Promosi [KLASTER 3]:
  * Lokasi: Panel Keranjang Belanja sisi kanan kasir -> Section "Diskon & Voucher Nota".
  * Tombol Kelola: Tekan tombol "+ Tambah Diskon" / "Kelola Diskon" untuk membuka accordion kontrol.
  * Input Diskon Nota:
    1. Pilih mode nominal: Tekan tombol "Rp" (Rupiah) atau "%" (Persentase).
    2. Masukkan angka pada kotak input (contoh: 10 untuk 10%, atau 15000 untuk Rp 15.000).
    3. Kasir juga dapat langsung menekan tombol preset instan:
       - Preset Persen: [5%], [10%], [15%], [20%].
       - Preset Rupiah: [5k], [10k], [20k], [50k].
    4. Tekan tombol "Terapkan" atau tekan [Enter]. Badge merah akan muncul mengonfirmasi nominal hemat.
    5. Untuk membatalkan diskon nota, cukup tekan ikon silang (X) pada badge.
  * Input Kode Voucher Promosi:
    1. Ketik kode voucher pada kolom input (contoh: HEMAT10, GRANDOPENING, MEMBER5, DISKON25K). Huruf otomatis dikapitalisasi.
    2. Atau langsung klik salah satu pill rekomendasi voucher aktif di bawah form input.
    3. Tekan tombol "Pakai" atau tekan [Enter].
    4. Validasi Otomatis:
       - Jika belanja mencukupi: Muncul badge emerald dengan notifikasi audio beep: "Voucher HEMAT10: Promo Hemat 10% (-Rp ...)" dan total bayar berkurang seketika.
       - Jika belanja belum mencapai syarat: Muncul peringatan jelas (contoh: "Minimal belanja untuk voucher ini adalah Rp 100.000 (Subtotal saat ini: Rp 72.000)").
    5. Untuk membatalkan voucher, tekan ikon silang (X) pada badge voucher hijau.
  * Transparansi Rincian Pembayaran:
    - Di layar kasir & dialog pembayaran checkout: Disajikan Subtotal Produk, Diskon Produk, Diskon Nota, Voucher Promo, Pajak, dan Total Tagihan Akhir.
    - Di Struk Thermal Kasir: Tercetak baris rincian khusus "Diskon Nota (X%): -Rp ..." dan "Voucher (KODE): -Rp ..." secara rapi dan transparan.
- Bukti Transaksi:
  * Transaksi yang berhasil akan langsung memunculkan "ReceiptModal" thermal printer
    yang siap dicetak via printer kasir (ESC/POS).

- Audit Mutasi Stok (Kartu Stok Elektronik):
  * Tekan tombol "Audit Mutasi" pada baris barang di tabel stok cabang atau gudang.
  * Modal akan menampilkan riwayat lengkap seluruh mutasi barang (SALE, PURCHASE,
    TRANSFER, ADJUSTMENT) lengkap dengan cap waktu, delta (+/-), stok akhir, dan keterangan.

10.6. KONTROL SHIFT KASIR, KAS KECIL (PETTY CASH) & REKONSILIASI FISIK KAS LACI
---------------------------------------------------------------------------------
- Lokasi Menu :
  * Tombol "Kas Masuk / Keluar" di Navbar Kasir (Akses cepat 1-klik tanpa meninggalkan layar kasir).
  * Tombol icon kas di samping pilihan pelanggan pada panel keranjang kasir POS.
  * Halaman Manajemen Shift (Sidebar -> "Riwayat Shift").
- Buka Shift (Start Cash):
  * Kasir wajib memasukkan modal uang kas kecil awal di laci (contoh: Rp 200.000).
  * Sistem mengaktifkan sesi kerja kasir dan mencatat status shift "OPEN".
- Pencatatan Kas Keluar (Cash Out / Petty Cash):
  * Klik tombol "Kas Masuk/Keluar" di navbar atau tombol di keranjang kasir.
  * Pilih tab "Kas Keluar (Cash Out)".
  * Masukkan nominal uang yang dikeluarkan (contoh: Rp 25.000) atau klik tombol chip cepat (+10k, +20k, +50k).
  * Pilih Kategori Biaya: "Operasional (Kresek, Lakban, ATK)", "Bahan Baku (Es Batu, Air Galon, Gas)",
    "Kurir & Ekspedisi (COD / Ongkir)", "Konsumsi Karyawan", atau "Lainnya".
  * Isi Catatan Keterangan: Contoh "Beli es batu kristal 2 kantong darurat karena habis".
  * Tekan tombol "Simpan Kas Keluar". Sistem langsung memotong nilai estimasi laci kasir secara realtime.
- Pencatatan Kas Masuk (Cash In / Suntikan Kas):
  * Klik tombol "Kas Masuk/Keluar".
  * Pilih tab "Kas Masuk (Cash In)".
  * Masukkan nominal uang yang dimasukkan (contoh: Rp 100.000).
  * Pilih Kategori: "Tambah Modal Kembalian (Dari Owner)", "Suntikan Kas Kasir", "Pendapatan Lain-lain".
  * Isi Catatan Keterangan: Contoh "Suntikan receh 2.000-an dan 5.000-an dari Pak Budi".
  * Tekan tombol "Simpan Kas Masuk". Sistem langsung menambah nilai estimasi laci kasir.
- Proteksi Anti-Overdraft (Pencegahan Kas Minus):
  * Sistem otomatis memantau saldo uang kas di laci secara live.
  * Jika kasir menginput pengeluaran yang melebihi uang kas laci saat ini, sistem langsung
    menolak dan menampilkan peringatan: "Uang kas di laci tidak mencukupi untuk pengeluaran ini!".
- Tutup Shift & Cetak Struk Rekap (Z-Report):
  * Di akhir jam kerja, kasir menekan tombol "Shift Buka ... • Tutup Shift" di navbar atau tombol "Tutup Shift" di halaman shift.
  * Dialog penutupan shift menampilkan rincian transparan:
    * Modal Awal: Rp 200.000
    * (+) Penjualan Tunai: +Rp 500.000
    * (+) Kas Masuk (Suntik Modal): +Rp 100.000
    * (-) Kas Keluar (Petty Cash): -Rp 25.000
    * (=) Estimasi Fisik Laci: Rp 775.000
  * Kasir menghitung fisik uang tunai di laci dan mengetikkan Rp 775.000.
  * Sistem mendeteksi selisih Rp 0 ("Kas Cocok / Seimbang").
  * Kasir menekan tombol "Tutup Shift & Cetak Z-Report".
  * Dialog struk thermal Z-Report otomatis muncul dengan efek visual konfeti keberhasilan.
  * Tekan tombol "Cetak Struk Rekap (Z-Report)" untuk mencetak struk kasir melalui printer thermal (58mm/80mm).
  * Struk ditandatangani oleh Kasir dan Manajer Toko, kemudian dimasukkan ke dalam amplop setoran uang fisik bank.
- Cetak Pembacaan Kas Sementara (X-Report):
  * Kasir atau Supervisor dapat sewaktu-waktu mencetak struk pembacaan kas sementara saat shift masih berjalan.
  * Tekan tombol "Cetak X-Report" pada dialog Tutup Shift atau pada banner Shift Aktif di halaman "Riwayat Shift".
- Cetak Ulang Struk Rekap Shift Lalu (Reprint Z-Report):
  * Di halaman "Riwayat Shift" (Sidebar -> "Riwayat Shift"), setiap baris sesi shift kasir dilengkapi tombol "Cetak".
  * Kasir atau Manajer dapat mencetak ulang struk Z-Report sesi shift kapan pun dibutuhkan untuk keperluan audit dan arsip.
- Audit & Rincian Shift (Riwayat Shift):
  * Di halaman "Riwayat Shift", owner dan manajer dapat melihat kolom "KAS MASUK" dan "KAS KELUAR".
  * Tekan tombol "Rincian" pada baris shift untuk melihat rekap lengkap ringkasan finansial dan
    seluruh daftar mutasi kas kecil shift tersebut (siapa yang mencatat, jam berapa, kategori, dan nominal),
    serta terdapat tombol langsung "Cetak Struk Rekap" di dalam modal rincian tersebut.

10.7. MANAJEMEN PELANGGAN (CRM) & KONTROL PIUTANG / KASBON
-----------------------------------------------------------
- Lokasi Menu : Sidebar -> "Data Pelanggan" (Akses: Semua Role).
- Fitur & Manajemen Piutang:
  * Mendaftarkan nama pelanggan, nomor WhatsApp/HP, dan email.
  * Ringkasan KPI Finansial di atas tabel: Total Pelanggan, Total Kasbon / Piutang Toko, dan Jumlah Pelanggan yang Belum Lunas.
  * Kolom "STATUS PIUTANG / KASBON": Menampilkan badge warna merah terang nominal kasbon aktif dan jumlah nota belum lunas (contoh: "Rp 150.000 • 2 nota kasbon"), atau badge hijau "Rp 0 (Lunas)".
  * Pelanggan yang terdaftar otomatis dapat dicari di layar kasir POS.
- Prosedur Operasional Catat Pelunasan Kasbon (Settle Customer Debt):
  1. Pada halaman "Data Pelanggan", klik tombol "Catat Pelunasan" (tombol hijau) pada baris pelanggan yang memiliki saldo kasbon aktif.
  2. Modal Pelunasan menampilkan rekap total piutang dan daftar nota kasbon pelanggan (Nomor Nota TRX, Tanggal Transaksi, Tanggal Jatuh Tempo, dan Sisa Piutang). Peringatan "(Lewat!)" muncul secara otomatis jika tanggal jatuh tempo sudah terlewati.
  3. Kasir dapat memilih nota spesifik yang ingin dilunasi atau menggunakan mode otomatis "FIFO" (First In First Out / nota tertua dilunasi terlebih dahulu).
  4. Masukkan nominal pembayaran (tersedia tombol cepat "Lunasi Penuh" atau bayar cicilan sebagian).
  5. Pilih metode pembayaran pelunasan: Tunai (CASH), QRIS, Transfer Bank, atau Debit EDC.
  6. Tambahkan catatan pelunasan (opsional, misal: "Titip bayar via transfer Mandiri").
  7. Klik "Simpan Pelunasan Kasbon".
- Sinkronisasi Otomatis Kas Laci Kasir (Cash Drawer & Cash In Auto-Sync):
  * Jika kasbon dilunasi secara TUNAI (CASH) dan staf kasir sedang membuka sesi shift aktif, sistem secara otomatis mencatat mutasi `CashMovement` tipe `CASH_IN` kategori "Pelunasan Kasbon".
  * Saldo fisik laci kasir dan `expectedCash` di sistem shift bertambah secara otomatis dan presisi, sehingga saat kasir tutup shift, uang fisik laci tetap seimbang dengan selisih Rp 0.

10.10. PENGATURAN IDENTITAS TOKO & KUSTOMISASI STRUK THERMAL (58MM & 80MM)
--------------------------------------------------------------------------
- Lokasi Menu : Sidebar -> "Pengaturan Struk" (Akses: Outlet Manager, Tenant Owner).
- Panduan Langkah demi Langkah (Step-by-Step Operator & Admin Guide):
  1. Masuk ke menu "Pengaturan Struk" di sidebar kiri.
  2. Memilih Format Printer Thermal:
     * Klik kartu "58 mm": Jika kasir menggunakan printer bluetooth mini atau printer kasir portable USB.
     * Klik kartu "80 mm": Jika kasir menggunakan printer desktop ritel besar (Epson TM-T82, Janz, Matrix Point).
  3. Mengatur Logo Struk Toko:
     * Pastikan centang "Tampilkan Logo" aktif.
     * Klik tombol "Unggah Logo (File)" untuk memilih gambar logo dari komputer (PNG/JPG maksimal 2MB).
     * Gambar otomatis dikonversi dan ditampilkan pada pratinjau struk di panel sebelah kanan.
     * Jika ingin menghapus logo, cukup klik tombol merah "Hapus".
  4. Mengisi Identitas & Kontak Toko:
     * Masukkan "Nama Toko / Bisnis" (wajib).
     * Masukkan "Alamat Lengkap Outlet" (wajib).
     * Masukkan "No. Telepon / WhatsApp" dan "Akun Instagram" toko.
     * Berikan centang "Tampilkan Kontak & Media Sosial di Struk".
  5. Mengatur Catatan Kaki Struk (Footer Note):
     * Kasir/Manajer dapat mengetik pesan khusus di textarea "Catatan Kaki Struk".
     * Tersedia tombol template cepat sekali klik:
       - [Standar Ritel]: "Barang yang sudah dibeli tidak dapat ditukar atau dikembalikan. Terima kasih atas kunjungan Anda!"
       - [Garansi Retur]: "Simpan struk ini sebagai bukti pembayaran sah. Garansi tukar produk cacat pabrik maksimal 1x24 jam."
       - [F&B / Kafe]: "Selamat menikmati hidangan kami! Kritik, saran, & pesanan catering hubungi WhatsApp kami."
  6. Uji Coba Printer Fisik (Tes Cetak):
     * Klik tombol "Tes Cetak Sampel" di bagian atas halaman.
     * Kotak dialog cetak printer bawaan browser akan terbuka.
     * Pastikan printer thermal kasir Anda terpilih, lalu tekan Print.
     * Verifikasi hasil cetak fisik pada kertas thermal: teks tidak terpotong dan logo tercetak jelas.
  7. Menyimpan Pengaturan:
     * Klik tombol hijau "Simpan Perubahan".
     * Muncul pesan konfirmasi: "Pengaturan struk dan identitas toko berhasil disimpan!".
     * Seluruh kasir di outlet terkait akan langsung mencetak struk dengan identitas baru tersebut tanpa perlu restart aplikasi.
  8. Penggunaan di Layar Kasir POS:
     * Setelah setiap transaksi selesai di kasir POS, dialog struk ("ReceiptModal") otomatis memuat
       logo, nama toko, alamat, kontak, dan footer baru yang telah diatur.
     * Kasir juga dapat mengubah ukuran kertas (58mm / 80mm) secara on-the-fly melalui toggle bar
       di bagian atas struk kasir sebelum menekan tombol "Cetak Struk Thermal".

10.13. GENERATOR CETAK LABEL BARCODE CODE 128 & PRICE TAG RAK MINIMARKET
-----------------------------------------------------------------------------
- Lokasi Menu : Sidebar -> "Katalog & Produk" (Akses: Semua Role)
- Tombol Aksi :
  * [Cetak Barcode / Price Tag] di header: Cetak massal banyak produk.
  * [Label] di setiap baris tabel produk: Cetak cepat label untuk produk tunggal tersebut.
- Panduan Langkah demi Langkah (Step-by-Step Operator Guide):
  1. Membuka Generator Barcode:
     * Masuk ke menu "Katalog & Produk".
     * Klik tombol "Cetak Barcode / Price Tag" di header (atau tombol "Label" pada produk tertentu).
     * Modal Generator Barcode interaktif akan terbuka.
  2. Memilih Template Label yang Diinginkan:
     * Pilih salah satu dari 3 template yang tersedia di panel kiri:
       - [Price Tag Rak Minimarket (60 x 40 mm)]: Format standar minimarket dengan nama toko,
         nama barang, satuan/kategori, harga ritel besar mencolok, dan barcode garis Code 128.
       - [Stiker Barcode Produk (40 x 30 mm)]: Ukuran kompak untuk ditempel langsung di kemasan produk.
       - [Lembar Kertas A4 (Grid Stiker)]: Format stiker multi-label Tom & Jerry untuk printer biasa.
  3. Mengatur Identitas Toko & Jumlah Label:
     * Masukkan "Header Toko Pada Label" (misal: "ZONA MART" atau nama outlet Anda).
     * Pada daftar produk di panel kiri, centang produk yang ingin dicetak.
     * Atur kolom "Jml" untuk setiap produk (misal: cetak 5 lembar untuk produk yang baru datang).
     * Tersedia tombol "Pilih Semua" untuk mencetak label seluruh katalog toko sekaligus.
  4. Pratinjau Interaktif (WYSIWYG Preview):
     * Panel sebelah kanan menampilkan pratinjau lembar stiker secara presisi dan realtime.
     * Barcode digambar dalam format vektor SVG tajam dengan teks SKU di bawahnya.
  5. Menjalankan Pencetakan:
     * Klik tombol "Cetak Label Sekarang".
     * Dialog cetak bawaan browser akan muncul:
       - Jika menggunakan Thermal Barcode Printer (Xprinter, Postek, Zebra): Atur ukuran kertas
         ke ukuran label Anda (60x40mm atau 40x30mm) dan margin ke "None".
       - Jika menggunakan Printer A4: Pilih kertas A4 portrait.
     * Tekan tombol "Print".
     * Stiker label dan price tag siap ditempel di rak etalase minimarket toko Anda!

10.14. MANAJEMEN PROMOSI & VOUCHER DISKON (KUPON PROMO TOKO)
-----------------------------------------------------------------------------
- Lokasi Menu : Sidebar -> "Promo & Voucher" (Akses: Outlet Manager, Tenant Owner)
- Komponen UI : PromotionsPage.jsx
- Endpoint REST API Terkait:
  * GET /api/v1/promotions/all: Mengambil semua daftar kupon promosi milik tenant bisnis.
  * POST /api/v1/promotions: Membuat kupon promo baru dengan validasi fail-fast.
  * PUT /api/v1/promotions/{id}: Mengubah konfigurasi diskon, plafon, kuota, atau masa berlaku kupon.
  * DELETE /api/v1/promotions/{id}: Menghapus kupon promo dari database toko.
  * PATCH /api/v1/promotions/{id}/toggle-status: Mengubah status aktif/non-aktif secara instan (1-klik).
  * GET /api/v1/promotions?outletId=X: Mengambil kupon aktif yang siap digunakan oleh kasir POS.
  * POST /api/v1/promotions/validate: Memvalidasi kelayakan kupon terhadap subtotal belanja kasir.

- Fitur-Fitur Utama Modul:
  1. Ringkasan KPI Eksekutif (4 Kartu Metrik):
     * Total Voucher Promo: Menghitung total semua kupon dalam basis data tenant.
     * Kupon Aktif Berjalan: Kupon yang berstatus aktif, belum kedaluwarsa, dan kuota masih tersedia.
     * Total Digunakan (Klaim): Akumulasi jumlah transaksi penjualan yang telah sukses menikmati diskon voucher.
     * Habis Kuota / Kedaluwarsa: Kupon yang sudah tidak dapat dipakai lagi oleh kasir.
  2. Mode Tampilan Ganda (Dual View Mode):
     * Tampilan Kartu Voucher (Voucher Cards): Desain tiket voucher dengan aksen border putus-putus,
       notch lingkaran di tepi kartu, tombol salin kode cepat, informasi diskon, syarat belanja,
       visual progress bar pemakaian kuota, dan sakelar instan.
     * Tampilan Tabel Rinci (Detailed Table): Tampilan tabel padat untuk memonitor puluhan kupon sekaligus
       lengkap dengan kolom kode, nama promo, target cabang, persentase/nominal diskon, min. belanja,
       rasio kuota, masa berlaku, status badge, sakelar toggle, dan tombol aksi.
  3. Pemfilteran & Pencarian Multidimensi:
     * Pencarian real-time berdasarkan kode kupon (misal: "HEMAT", "GAJIAN") atau nama promo.
     * Filter status: Semua, Aktif Berjalan, Non-Aktif, Kedaluwarsa, Kuota Habis.
     * Filter tipe diskon: Semua Tipe, Persentase (%), Nominal Tetap (Rp).
     * Filter target outlet: Semua Cabang (Nasional) atau Cabang Tertentu.
  4. Sakelar Status Instan (Instant Toggle Switch):
     * Memungkinkan Owner/Manager menghentikan atau mengaktifkan kembali promosi dalam 1-klik tanpa
       harus membuka formulir edit. UI diperbarui secara optimistik dengan respon instan.
  5. Monitoring Kuota Pemakaian Transparan:
     * Bar kuota otomatis menyesuaikan warna (Hijau: Aman, Kuning: >=80% kuota, Merah: 100% Habis).
     * Menampilkan perbandingan angka nyata times_used dari usage_limit.

- Panduan Langkah demi Langkah (Step-by-Step Operator Guide):
  1. Membuat Kupon Promosi Toko Baru:
     * Buka menu "Promo & Voucher" pada bilah navigasi sidebar kiri.
     * Klik tombol hijau "+ Buat Kupon Promo" di sudut kanan atas.
     * Modal pembuatan kupon akan muncul dengan 2 panel (Formulir Pengaturan & Live Card Preview).
     * Masukkan "Kode Kupon Promo" (otomatis berhuruf kapital, misal: HEMAT20, DISKON50K),
       atau klik tombol "+ Acak Kode" untuk membuat kode unik otomatis.
     * Masukkan "Nama Promosi" (misal: "Promo Gajian Weekend Ceria").
     * Masukkan "Deskripsi Promosi" (opsional, catatan syarat promo).
     * Pilih "Target Cabang (Outlet)": Pilih [Semua Cabang (Nasional)] agar kupon berlaku di seluruh toko,
       atau pilih cabang outlet spesifik jika promo merupakan program khusus cabang tertentu.
     * Pilih "Tipe Diskon":
       - [Persentase (%)]: Masukkan angka persen (misal: 10) dan isi "Maksimal Diskon (Plafon Rp)"
         (misal: Rp 30.000) untuk mencegah diskon berlebih pada nota bernilai besar.
       - [Nominal Tetap (Rp)]: Masukkan nominal potongan langsung rupiah (misal: Rp 25.000).
     * Tentukan "Syarat Minimal Belanja Nota (Rp)" (misal: Rp 50.000, atau isi 0 jika tanpa syarat).
     * Konfigurasi Pembatasan:
       - Centang "Batasi Periode Masa Berlaku Promo" jika promo memiliki tanggal & jam mulai serta tanggal & jam kedaluwarsa.
       - Centang "Batasi Kuota Jumlah Pemakaian" jika promo dibatasi untuk sejumlah pelanggan/transaksi pertama (misal: 100x klaim).
       - Periksa sakelar "Status Promo Langsung Aktif".
     * Perhatikan panel kanan "Pratinjau Kartu Kupon (Live Preview)" untuk memastikan tampilan kupon sudah sesuai.
     * Klik tombol "Buat Voucher Kupon". Kupon langsung aktif dan siap digunakan kasir di meja pembayaran.

  2. Mengubah atau Memperbarui Kupon Promosi:
     * Cari kupon pada daftar menggunakan kotak pencarian atau filter status.
     * Klik tombol "Edit" (ikon pensil).
     * Formulir akan terisi data kupon saat ini. Lakukan penyesuaian (misal: menambah kuota pemakaian atau memperpanjang tanggal berakhir).
     * Klik "Simpan Perubahan".

  3. Mengaktifkan / Menonaktifkan Promo Seketika:
     * Cukup klik sakelar toggle di baris tabel atau pada kartu kupon:
       - Ikon Toggle Hijau (Kanan): Kupon aktif dan kasir dapat menerapkannya.
       - Ikon Toggle Abu-abu (Kiri): Kupon dinonaktifkan sementara.

  4. Menghapus Kupon Promosi:
     * Klik tombol hapus (ikon tong sampah merah).
     * Modal konfirmasi peringatan akan muncul menampilkan kode dan nama promo.
     * Klik tombol "Ya, Hapus Kupon".

  5. Alur Pemakaian di Layar Kasir POS (PosKasir.jsx):
     * Kasir membuka transaksi penjualan seperti biasa dan memasukkan produk ke keranjang.
     * Di panel keranjang belanja, klik menu "+ Tambah Diskon" atau "Kelola Diskon".
     * Kasir dapat:
       - Mengetik kode kupon yang diberikan pelanggan pada kotak "Kode Voucher Promo" lalu menekan tombol "Pakai" (atau tekan Enter).
       - ATAU cukup klik salah satu chip tombol voucher aktif yang tersedia di bawah input tanpa perlu mengetik.
     * Sistem memvalidasi kupon secara instan:
       - Jika memenuhi syarat minimal belanja, voucher aktif, dan kuota tersedia: Diskon langsung memotong total belanja dan menampilkan pesan sukses berwarna hijau.
       - Jika subtotal kurang dari minimal belanja: Sistem memberi notifikasi penolakan ramah (misal: "Minimal belanja Rp 50.000, subtotal saat ini Rp 35.000").
     * Saat kasir menyelesaikan transaksi (Bayar), stok dipotong dan kuota pemakaian kupon (times_used) bertambah 1 secara atomik dengan perlindungan Pessimistic Locking.

10.15. BUKU REGISTER & JURNAL PEMBELIAN (REKAPITULASI PURCHASE ORDER)
-----------------------------------------------------------------------------
- Lokasi Menu : Sidebar -> "Stok & Gudang" -> Tombol "Jurnal Pembelian (PO)"
- Komponen UI : PurchaseOrderJournalModal.jsx (terintegrasi di InventoryPage.jsx)
- Endpoint REST API Terkait:
  * GET /api/v1/suppliers/purchase-orders: Mengambil seluruh histori dokumen PO belanja pengadaan dengan filter fleksibel (supplier, gudang, outlet, rentang tanggal, dan pencarian teks).
  * GET /api/v1/suppliers: Mengambil daftar master pemasok aktif.
  * POST /api/v1/stocks/purchase: Mencatat pengadaan barang masuk dan menerbitkan nomor PO unik (PO-YYYYMMDD-XXXX).

- Fitur-Fitur Utama Modul:
  1. Ringkasan KPI Keuangan Pengadaan (4 Metrik Utama):
     * Total Modal Pengadaan: Akumulasi nominal rupiah uang modal yang dibelanjakan ke supplier.
     * Total Dokumen PO: Jumlah dokumen purchase order yang pernah diterbitkan.
     * Total Barang Masuk: Akumulasi unit kuantitas barang yang telah diterima di gudang/toko.
     * Rata-Rata Nilai per PO: Nilai belanja rata-rata per transaksi pengadaan barang.
  2. Filter & Pencarian Cepat Multidimensi:
     * Pencarian instan berdasarkan No. PO (PO-...), No. Faktur/Invoice Vendor, Nama Produk, Nama Supplier, atau Catatan PO.
     * Filter rentang tanggal cepat: [Hari Ini], [7 Hari Terakhir], [30 Hari Terakhir], [Bulan Ini], [Semua Waktu], atau Custom Date Picker.
     * Filter Pemasok: Filter per mitra vendor/supplier spesifik.
     * Filter Lokasi Tujuan: Filter per Gudang Logistik atau Outlet Toko penerima.
  3. Tabel Register Jurnal Pembelian Komprehensif:
     * No. Dokumen PO (format unik PO-YYYYMMDD-XXXX) dengan tombol salin (copy) 1-klik.
     * Tanggal & Jam Penerimaan Barang Masuk.
     * Nama Mitra Supplier / Vendor.
     * Lokasi Penerima Barang (Badge Gudang Transit atau Outlet Toko).
     * Nama Produk & Varian Rasa/Ukuran.
     * Jumlah Kuantitas Masuk (Unit).
     * Harga Beli Modal Satuan (Rp) & Total Biaya Pengadaan (Rp bold mencolok).
     * No. Faktur / Invoice Eksternal Supplier.
     * Identitas Staff / User Penerima Barang.
  4. Modal Detail Faktur Purchase Order (Single PO Document Viewer):
     * Menampilkan lembar dokumen Purchase Order resmi untuk transaksi tunggal.
     * Dilengkapi rincian produk, kuantitas, harga modal, nomor faktur vendor, catatan, dan tombol cetak faktur PO satuan.
  5. Ekspor Data Excel Universal (.xlsx via SheetJS):
     * Mengunduh seluruh rekapitulasi jurnal pembelian ke file Excel terformat rapi untuk keperluan audit pembukuan dan akuntansi.
  6. Cetak Rekapitulasi PO Resmi A4 (Print Engine):
     * Pratinjau dokumen A4 resmi ber-kop surat toko, ringkasan KPI, tabel transaksi pengadaan terperinci, total biaya, dan kolom tanda tangan pengesahan ("Dibuat Oleh" & "Disetujui Oleh").

- Panduan Langkah demi Langkah (Step-by-Step Operator Guide):
  1. Membuka Buku Register & Jurnal Pembelian:
     * Masuk ke menu "Stok & Gudang" pada navigasi sidebar kiri.
     * Klik tombol hijau "Jurnal Pembelian (PO)" pada bilah aksi header atas.
     * Modal Buku Register & Jurnal Pembelian akan terbuka dalam tampilan layar lebar.
  2. Memantau & Memfilter Transaksi Pengadaan:
     * Perhatikan 4 kartu KPI di bagian atas untuk melihat total modal yang dibelanjakan ke supplier.
     * Gunakan tombol chip tanggal cepat (misal: klik [Bulan Ini] untuk melihat belanja bulan berjalan).
     * Pilih supplier tertentu pada dropdown "Supplier" jika ingin mengecek riwayat belanja ke vendor tertentu.
     * Ketik nama barang atau nomor faktur pada kotak pencarian untuk menemukan dokumen PO secara seketika.
  3. Melihat Rincian Dokumen Faktur PO:
     * Klik nomor PO (atau tombol "Faktur") pada baris tabel transaksi yang diinginkan.
     * Modal lembar faktur PO resmi akan tampil memuat data vendor, lokasi penerima, harga satuan, dan catatan.
     * Klik "Cetak Faktur PO" jika ingin mencetak bukti fisik penerimaan barang tersebut.
  4. Mengunduh Rekapitulasi ke Excel:
     * Pastikan filter data sudah sesuai dengan periode yang diinginkan.
     * Klik tombol "Download Excel" di pojok kanan atas.
     * File .xlsx otomatis terunduh ke komputer Anda dengan kolom yang terformat rapi.
  5. Mencetak Lembar Rekapitulasi Pengadaan (A4):
     * Klik tombol "Cetak Rekap PO".
     * Modal pratinjau dokumen formal A4 akan muncul.
     * Periksa tabel dan grand total biaya pengadaan, lalu klik "Cetak / Simpan PDF" pada dialog cetak browser.
